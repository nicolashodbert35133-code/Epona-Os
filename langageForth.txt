# 📘 EPONA FORTH — Le Langage Système d'Epona OS

> **Version** : 2.0-beta2 · **Conformité** : profil `EPONA-FORTH2012-CORE-1`
> **Dernière mise à jour** : 9 août 2026
> **Licence du langage** : MIT (le langage, les mots, les modules `.fth`) · Noyau Rust : propriétaire

> ⚠️ **Note importante depuis la refonte ISO 2012** : Epona Forth vise désormais la conformité **Forth 2012 Core**. La sémantique de nombreux mots a changé par rapport aux premières versions (flags, `2/`, `rshift`, modèle mémoire, `create`/`does>`). Ce document décrit le comportement **actuel et conforme**. Si vous avez du code écrit avant août 2026, relisez le chapitre 16 « Migration ».

# 🎯 Vue d'ensemble : un langage système intégré au kernel

Epona Forth n'est pas un « petit interpréteur ». C'est un **langage système**, intégré :

- au **shell**, au **window manager**, au **système de fichiers** (FAT32/VFS),
- au **GPU** (GOP/SimpleFB), au **PCI**, à l'**I2C HID**, au **MMIO**,
- au **PS/2** et à l'**USB xHCI** (clavier/souris),
- au **watchdog AMD FCH**, au **scheduler** coopératif/préemptif.

Depuis la refonte 2026, il vise en plus la **conformité Forth ISO 2012 Core**, ce qui signifie qu'un développeur ou un agent peut écrire du Forth **standard** exploitable directement sur le métal.

C'est un langage comparable à **Oberon**, mais en Forth, dans un OS UEFI bare-metal.

# 🧩 Chapitre 1 — Structure interne de la VM Forth

La VM contient :

### ✔ Une pile de données
`stack: Vec<i64>` — cœur du langage, profondeur nominale 4096 cellules (voir `ENVIRONMENT? STACK-CELLS`).

### ✔ Une pile de retour
`rstack: Vec<i64>` — 1024 cellules (`RETURN-STACK-CELLS`). Utilisée par `>r r> r@`, `do/loop`, les appels de mots et `catch/throw`.

### ✔ Un dictionnaire de mots
`dictionary: Vec<Word>` — chaque `Word` contient :
- `name: [u8; 64]` (NUL-terminé)
- `ops: Vec<Op>` — bytecode précompilé
- un flag immédiat

### ✔ Un buffer de sortie
`print_buffer: String` — utilisé par `.`, `."`, `u.`, `type`, `emit`, messages d'erreur.

### ✔ Un canvas graphique
`canvas: Canvas { width, height, buffer }` — cible de `fb:*` quand redirigé (`gfx:set-target-canvas`).

### ✔ Un callback de step
`step_callback: Option<fn(&mut ForthVm)>` — animations, rafraîchissement, souris/clavier, scheduling coopératif.

### ✔ Un flag d'arrêt d'urgence
`emergency_break: bool` — déclenché par **F9** (interruption d'un programme Forth qui boucle).

### ✔ **Nouveauté ISO 2012 — cellules système adressables**

Contrairement aux premières versions où l'état vivait dans des champs Rust invisibles, ces valeurs sont maintenant de **vraies adresses mémoire** lisibles/modifiables par `@`/`!` :

| Mot | Adresse | Rôle |
|-----|---------|------|
| `>in` | 65535 | Pointeur de parsing dans la source |
| `state` | 65534 | 0 = interprétation, ≠0 = compilation |
| `base` | 65533 | Base numérique courante (10, 16, 2…) |
| `hold` | 65532 | Pointeur de sortie numérique formatée |

Zone de sortie numérique (« pictured output ») : `[65464..65532)`. Buffer de `word` : `[65424..65464)`.

# 🧩 Chapitre 2 — Le modèle mémoire « fenêtre » ⚠️ À COMPRENDRE ABSOLUMENT

C'est **le changement le plus important** de la refonte. Il détermine ce que fait `c@`, `c!`, `@`, `!`, `move`, `fill`.

### Contrat d'adressage

- **1 unité d'adresse (AU) = 1 cellule de 64 bits (`i64`)**. Donc `cell` = 1, `char` = 1, `cells` et `chars` sont l'identité, `aligned` ne fait rien. (Permis par Forth 2012, qui autorise les « chars larges ».)
- Endianness : little-endian natif x86_64.

### La fenêtre de sécurité

```
Adresse < 65536  →  espace Forth  (self.memory[], sandbox check_mem)
Adresse ≥ 65536  →  MMIO / pointeur natif réel (matériel)
```

**Conséquence pratique :**

```forth
variable x
42 x !        \ écrit dans l'espace Forth sûr (x < 65536)
x @ .         \ 42

0xFED80300 mmio@ .   \ lit un registre matériel réel (≥ 65536)
```

Un `c!` sur une adresse basse **ne touche plus le matériel** — c'est voulu. Le code applicatif ne peut plus corrompre l'IDT ou une BAR par accident. Pour le bas niveau, on utilise explicitement les mots matériels (`mmio@`, `mmio!`, `pci:*`, ou une adresse `≥ 65536` obtenue par `mem:map-mmio`).

### Pourquoi c'est vital sur bare-metal

Sans OS en dessous, un accès mémoire sauvage ne provoque pas un segfault récupérable : il corrompt silencieusement le système ou provoque un triple fault. `check_mem` + la fenêtre sont **la seule ligne de défense**.

# 🧩 Chapitre 3 — Cycle de vie d'un programme Forth

### 3.1 Le shell reçoit une ligne

```
5 5 + .
```

Le shell appelle `forth_vm.compile(cmd)` puis exécute.

### 3.2 Compilation → `ops`

Le compilateur :
- découpe la ligne en tokens (via `parse-name` interne),
- nombre → `Op::Push(n)` (selon `base`),
- mot connu → `Op::Call(word_index)`,
- `:` … `;` → nouvelle définition,
- mots immédiats (`."`, `if`, `do`, `s"`…) → compilent directement, avec backpatch.

### 3.3 Exécution → interprétation directe des `ops`

Interpréteur direct (pas threaded code) **avec fallback garanti** : si le JIT est indisponible, l'interpréteur suffit. **Toute correction sémantique doit exister dans les deux chemins** (interpréteur ET JIT).

# 🧩 Chapitre 5 — La pile

`dup drop swap over rot -rot nip tuck 2dup 2drop 2swap 2over ?dup pick depth`

> **Corrigé depuis 2026** : `-rot ( a b c -- c a b )` et `tuck ( a b -- b a b )` avaient une implémentation fausse (respectivement identique à `rot`, et copie du bas de pile). **C'est corrigé.** Vérifiez votre ancien code qui aurait pu compenser ces bugs.

```forth
5 10 swap . .   \ affiche : 5 10
1 2 3 -rot .s   \ pile : 3 1 2
```

# 🧩 Chapitre 6 — Arithmétique et nombres

`+ - * / mod /mod 1+ 1- 2+ 2- 2* 2/ min max abs negate hasard`
Double cellule : `2@ 2! s>d m* */ */mod um* um/mod u<`

> **Corrigé** : `2/` est un **décalage arithmétique** (arrondi vers −∞ : `-5 2/` = `-3`, pas `-2`). `/`, `mod`, `/mod` sont en **division symétrique** (troncature vers zéro). `*/`, `um*`, `um/mod` utilisent un intermédiaire 128 bits (plus d'overflow silencieux).

```forth
5 5 + .        \ 10
-7 3 /mod . .  \ reste -1, quotient -2
```

# 🧩 Chapitre 7 — Comparaisons et logique

`= <> < > <= >= 0= 0<> 0< 0> u< and or xor invert lshift rshift within u>`

> ⚠️ **CHANGEMENT MAJEUR** : les comparaisons renvoient maintenant **`-1` (vrai)** et **`0` (faux)**, conformément à ISO 2012 — plus `1`.

```forth
10 20 < .      \ -1  (vrai)
5 5 = .        \ -1
5 6 = .        \ 0
```

> **Corrigé** : `rshift` est un **décalage logique** (remplit avec des zéros), `lshift` aussi. Si vous décaliez des valeurs négatives en attendant une extension de signe, utilisez `2/` répété ou l'arithmétique.

# 🧩 Chapitre 8 — Contrôle de flux (enrichi)

Bien plus que `if/then` :

```forth
\ Conditionnelle
: test dup 10 < if ." petit" else ." grand" then ;

\ Boucle indéfinie
: attente begin touche? until ;

\ Boucle while/repeat
: pompe begin lire ?assez while traiter repeat ;

\ Boucle comptée
: table 10 0 do i . loop ;
: pas2  10 0 do i . 2 +loop ;

\ Sortie anticipée
: cherche 100 0 do i cible = if i . unloop exit then loop ;

\ CASE
: nom-jour case
    1 of ." lundi"    endof
    2 of ." mardi"    endof
    ." autre" dup .
  endcase ;

\ Exceptions
: risqué ['] peut-planter catch if ." erreur rattrapée" then ;
```

Le compilateur gère les backpatches via une pile interne (`Jump`, `JumpIfZero`, adresses de `do`/`leave`).

# 🧩 Chapitre 9 — Mémoire, variables, données

### Variables et constantes

```forth
variable x       \ alloue 1 cellule dans HERE, adresse réelle
42 x !  x @ .    \ 42
10 constant DIX  \ valeur pure, pas d'adresse
5 value cpt      \ variable modifiable par TO
7 to cpt  cpt .  \ 7
```

> **Corrigé** : `variable` retourne désormais une **vraie adresse mémoire** (avant : un index de map dépendant de l'ordre de compilation). `create`/`does>` insèrent le body **avant** l'`Exit` (le pattern `create , does> @` fonctionne).

### Accès mémoire (dans la fenêtre)

`@ ! +! c@ c! w@ w! l@ l! 2@ 2! fill cmove move erase here allot , c,`

### Créer un tableau

```forth
create tab  100 allot     \ 100 cellules réservées
42 tab 5 + !              \ tab[5] = 42
tab 5 + @ .               \ 42
```

### Simuler une structure

```forth
create point  2 allot
10 point !                \ x à point+0
20 point 1 + !            \ y à point+1
```

# 🧩 Chapitre 10 — Chaînes

```forth
." Bonjour EponaOS"           \ affichage immédiat compilé
s" texte" type               \ ( addr len ) puis affichage
s" abc" swap drop .          \ longueur : 3
```

> **Corrigé** : `s"` compilé ne recopie plus la chaîne dans `HERE` **à chaque exécution** (ancien bug : dérive mémoire infinie en boucle). La chaîne est copiée une seule fois à la compilation ; l'op pousse `(addr len)`.

> **Limite documentée** : une chaîne `."`/`s"`/`abort"` **ne doit pas contenir `(` ni `)`** (le stripping des commentaires s'applique à tous les tokens).

Sortie numérique formatée : `<# # #s hold sign #> .r u.r`
```forth
: .money ( n -- ) <# # # [char] , hold #s #> type ;
125 .money      \ 1,25
```

# 🧩 Chapitre 15 — Étendre le langage

## 15.1 Ajouter un opcode (Rust)

```rust
// 1. enum Op
Sin,
// 2. compilateur
"sin" => ops.push(Op::Sin),
// 3. execute_ops — attention : bornes, pas d'unwrap sur entrée user
Op::Sin => {
    let a = self.stack.pop().ok_or("stack underflow")?;
    let r = (a as f64).sin();
    self.stack.push(r as i64);
}
```

> ⚠️ **Bare-metal** : jamais de `unwrap()` sur une valeur venue de Forth. Un panic Rust = machine figée. Toujours `ok_or(...)` et propager l'erreur. **Et répliquer dans jit.rs** si le mot doit être JITé.

## 15.2 Mot système

# 🧩 Chapitre 16 — Nombres décimaux (deux approches)

## Approche A — Entiers scalés (recommandée pour drivers/embarqué)

Représenter `1,25` par l'entier `125` (facteur 100). Déterministe, rapide, sans FPU.

```forth
\ DECIMAL.FTH
: scale   ( n -- n' ) 100 * ;
: *2dec   ( a b -- c ) * 100 / ;
: /2dec   ( a b -- c ) 100 * swap / ;
: .2dec   ( n -- )
    100 /mod
    swap 0 .r [char] , emit
    dup 10 < if [char] 0 emit then
    0 .r ;

125 200 + .2dec        \ 3,25
125 200 *2dec .2dec    \ 2,50
```

Conversion capteur → volts :
```forth
: adc>volt ( raw -- centivolt ) 330 * 4095 / ;
0xFEDC9000 sensor:read adc>volt .2dec ." V"
```

## Approche B — Flottants IEEE 754 (nouveau)

> **Le texte d'origine disait « pas de flottants ». C'est faux depuis les primitives 900-944.**

Epona dispose d'une pile flottante et d'opérations IEEE 754 : `f+ f- f* f/ f< f= f0< fsqrt fsin fcos …`. Utile pour le calcul scientifique, le graphique avancé, l'IA (Phase 7).

**Recommandation** : pour les **drivers industriels et l'embarqué**, préférez l'approche A (entiers scalés) — déterministe et sans dépendance FPU. Réservez les flottants au calcul applicatif.

# 🧩 Chapitre 17 — Migration depuis l'ancien Epona Forth (< août 2026)

Checklist pour porter du code antérieur à la refonte :

- [ ] **Flags** : remplacer les tests `= 1` par `0<>` ou tester `-1`. Tout code lisant `1` comme vrai est cassé.
- [ ] **`2/` négatif** : arrondit maintenant vers −∞.
- [ ] **`rshift`** : décalage logique (zéros). Extension de signe → utiliser `2/` répété.
- [ ] **`-rot`, `tuck`** : maintenant corrects. Retirer les contournements éventuels.
- [ ] **`c@`/`c!` sur adresse basse** : ne touche plus le MMIO. Utiliser `mmio@`/`mmio!` ou une adresse `≥ 65536`.
- [ ] **`variable`** : retourne une adresse réelle (plus un index). Le code qui présumait des adresses `0,1,2…` est à revoir.
- [ ] **`s"` en boucle** : plus de fuite `HERE` — comportement désormais correct.
- [ ] **Chaînes** : pas de `(` ni `)` dans `."`/`s"`.
- [ ] **`cells`/`chars`/`aligned`** : identité (1 AU = 1 cellule). Le code qui multipliait par 8 est faux.

Profil cible à déclarer dans vos modules : `EPONA-FORTH2012-CORE-1`.
