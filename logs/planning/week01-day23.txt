1) DECISION - UNITE D'ADRESSE
   Option validee : 1 UNITE D'ADRESSE = 1 CELLULE i64 (chars larges 64 bits,
   permis par Forth 2012 3.1.2.3). Pas de migration Vec<u8> (option B ecartee
   : casse JIT/atomic/variables/f64 pour un gain mineur).
   Consequence : CELL = 1, CHAR = 1, CELLS/CHARS = identite, CELL+ = +1,
   CHAR+ = +1, ALIGNED = identite.

2) CODE MODIFIE (src/interpreter.rs)
   - primitive 152 cell+ (l.2836-2840) : +8 -> +1 ;
   - primitive 153 cells  (l.2841-2845) : n*8 -> n (identite) ;
   - primitive 154 aligned (l.2846-2850) : align-8 -> identite ;
   - char+ (155, +1) et chars (156, identite) : inchanges, deja coherents.
   Impact verifie : ces mots etaient INUTILISES par tout le code Forth du
   projet (grep cells|aligned|char+|chars -> seulement des commentaires).

3) MOTS CELL / CHAR
   Premier essai : primitives natives 171/172 -> CONFLIT avec nvme:init (171)
   et nvme:read (172), enregistrees en double (l.781-782 vs l.1251). Retire.
   Solution retenue : constantes Forth au boot (aucun risque de collision) :
      forth/boot/BOOT.FTH :
        1 constant cell
        1 constant char
   (token constant interprete : `val constant nom`, l.12287-12309).
