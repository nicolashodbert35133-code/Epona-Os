2) DECOUVERTE MAJEURE - MODELE SOURCE
   compile() appelle set_source UNE fois avec TOUT le fichier charge
   (interpreter.rs l.10765 ; appels sys:load l.12036, boot l.6464) et
   >IN est un residu global (le test B4 `>in 5 !` laissait 5 pour toute
   la suite du fichier). Les tests B7/B8 d'origine supposaient
   "source = ligne courante avec >IN=0" -> NON DETERMINISTES (ROUGES) :
   - B7#1 `(commentaire avec x) t-pname` attendait u=11 mais parse-name
     lit la source du FICHIER depuis >IN -> "\" (u=1) ou "===" (u~78) ;
   - B7#2/#3/#4 et B8#2/#3/#4 idem (parse depuis une position parasite).

3) CORRECTIONS TESTS (core2012.fth)
   - Tous les tests B7/B8 reecrits en SOURCE CONTROLEE : `s" ..." evaluate`
     (set_source remet >IN a 0) pour les chaines sans parenthese ;
   - cas "parenthese atomique" (B7#1, nom "t-px(c" u=7) et "espaces
     initiaux" (B7#2, source "   t-pspaces") : `s"` eclate les parenthese
     en tokens separes et ne peut pas produire d'espaces initiaux (les
     espaces de la ligne sont des separateurs) -> CHAINE CONSTRUITE OCTET
     PAR OCTET dans memory puis executee via `evaluate` ;
   - B4 : `>in 5 ! >in @ .` laissait un residu global -> restaure par
     `0 >in !` en fin de ligne ;
   - B6 : residus de pile (`here find` sans cleanup) nettoyes (`2drop`,
     `drop`) ; le test `rot drop` (inexact avec la pile polluee) est
     remplace par `drop` + comparaison directe du flag.
