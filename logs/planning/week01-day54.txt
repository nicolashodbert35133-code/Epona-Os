MODIFICATIONS (src/interpreter.rs)
----------------------------------
1. Champ `caught_code: Option<i64>` (sentinel) ajouté à la struct de l'interpréteur.
   Reset à None dans abort/quit et dans le handler CATCH.
2. throw (primitive 199) — correction :
   - n == 0 (THROW 0) : no-op, le 0 est retiré, exécution continue.
   - n != 0 : recherche du handler le plus récent ; piles (données + retour +
     boucles) restaurées aux profondeurs sauvegardées ; code poussé.
   - handler = sentinelle (catch_ip == 0) -> caught_code posé + break de la
     définition en cours (CATCH interprété).
   - aucun handler -> Err("Throw non rattrapé") (arrêt de la source).
3. Op::Throw (compilé) — factorisé dans la nouvelle méthode `throw_impl`
   (restauration piles + push code + sentinelle caught_code / repositionnement
   ip). Retourne Ok(true) si le caller doit interrompre son exécution.
4. Op::AbortQuote — CORRIGÉ : `return Err("abort")` (stoppait tout sans
   exception) -> affiche le message puis `throw_impl(-2)` = THROW -2
   (Forth 2012 6.1.0685), capturable par CATCH.
5. within (prim 1833) — CORRIGÉ :
   - Bug 1 : lisait `stack.last()` sans dépiler n -> n restait sur la pile
     (résidus qui polluaient tous les tests suivants). Utilise `pop()`.
   - Bug 2 : comparaison signée lo<=n<hi -> formule standard 6.2.2440
     `(n-lo) U< (hi-lo)` en u64 wrapping (gère les plages circulaires lo>hi).
6. Handler `catch` en mode interprété (state 0), ajouté après `action-of` :
   - pop xt -> stack_d/rstack_d/loop_d, push (…, 0) sentinelle, execute_ops(xt).
   - pop du handler ; si caught_code None (exécution normale) -> push 0,
     sinon le code a DÉJÀ été poussé par throw (ne pas re-pousser).
7. Check `caught_code` en début de boucle execute_ops_limited : si Some,
   on retourne Ok immédiatement (la définition appelante stoppe proprement).

HOLDS (1836) — vérifié FAUX POSITIF : la boucle (0..u).rev() avec hp2--
place caddr[0] à l'adresse la plus basse -> ordre préservé. NON modifié.

LIMITES CONNUES
---------------
- `postpone if / else / then` non supporté (mots de compilation structurés) :
  -> "Mot inconnu". À implémenter plus tard si besoin.
- La sémantique exacte de compilation d'un mot immédiat via `postpone`
  (qui devrait différer de sa sémantique d'exécution) n'est pas distincte :
  `postpone get-2drop` exécute le mot (Op::Call) au runtime.
