FICHE DE MODIFICATION - ARITHMETIQUE SIGNEE (2/ + verification / MOD /MOD)
--------------------------------------------------------------------------

1) ANALYSE (verification code avant modification)
   a) 2/  (interpreter.rs idx 52, l.1884) : "v / 2" -> troncature vers zero.
      Norme Forth 2012 : 2/ = decalage arithmetique a droite d'un bit
      (quotient arrondi vers -infini). Ex : -5 2/ = -3 (aujourd'hui -2).
      FIX : "v >> 1" (Rust : shift arithmetique sur i64, bien defini pour
      tout entier y compris MIN).
   b) 2/  (JIT prim_2slash, jit.rs l.2057) : "shr_imm8(1, R13)". VERIFIE :
      shr_imm8 (jit.rs l.538) emet 0xC1 /7 = SAR (shift ARITHMETIQUE), pas
      SHR. Donc le JIT est DEJA correct pour 2/ (et divergent de l'interpret
      eur actuel). Renommer shr_imm8 -> sar_imm8 pour lever l'ambiguite
      (2 appelants : prim_2slash l.2057 et prim_abs l.2062 - les deux
      veulent SAR).
   c) /  (interpreter idx 3, l.1495) : "a / b" Rust -> troncature vers zero.
      mod (idx 4, l.1500) : "a % b" Rust -> reste signe = dividende.
      /mod (idx 57, l.1897-1901) : push(a%b) puis push(a/b) -> quotient au
      sommet. Ce sont des divisions SYMETRIQUES : conformes a la suite de
      tests CORE ANS/2012 (T{ -7 3 / -> -2 }, T{ 7 -3 / -> -2 },
      T{ -7 3 MOD -> -1 }, T{ 7 -3 MOD -> 1 }, T{ -7 3 /MOD -> -2 -1 }).
      JIT (prim_div/prim_mod/prim_divmod via idiv, l.1815-1831) : idem.
      CONCLUSION : / mod /mod NE SONT PAS A REECRIRE (sans reecriture
      inutile, conformes). Des tests negatifs sont ajoutes pour le prouver.
   d) BUG LATENT DECOUVERT : parse_number_with_base (l.12810)
      "Ok(-(val as i64))" : pour le litteral decimal MIN -9223372036854775808,
      val as i64 = MIN puis -MIN => PANIQUE en debug (overflow). Le test de
      valeur limite MIN le declencherait. FIX : "Ok((val as i64).wrapping_neg())".
      Hex 0x8000000000000000 est deja sur (Ok(val as i64)) et -1 63 lshift
      (wrapping) aussi.

2) PERIMETRE DES CHANGEMENTS
   - interpreter.rs : idx 52 (v / 2 -> v >> 1) + parse_number_with_base
     (wrapping_neg).
   - jit.rs : renommage shr_imm8 -> sar_imm8 (aucun changement de code emis).
