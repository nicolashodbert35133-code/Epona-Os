1. SAVE-INPUT / RESTORE-INPUT  (src/interpreter.rs, primitives 1837/1838)
--------------------------------------------------------------------------------
Avant  : save-input ( -- flag ) avec Vec Rust interne input_snapshots ;
         restore-input ( flag -- flag ).
Apres  : conforme ISO Forth 2012 (6.2.2182 / 6.2.2148) :

    save-input   ( -- x3 x2 x1 3 )   x3 = source_addr,
                                     x2 = source_buffer_len,
                                     x1 = >IN, puis n = 3 au sommet.

    restore-input ( x3 x2 x1 n -- flag )
        - depile n ; si n != 3 : depile n elements si possible, push -1 (echec)
        - si n == 3 : depile to_in, src_len, src_addr ; restaure source_addr
          et >IN ; push 0 (succes).

Champ `input_snapshots: Vec<(String, usize, i64)>` SUPPRIME de ForthVm
(definition ~l.371 + initialisation ~l.493). L'etat vit desormais uniquement
sur la pile de donnees Forth.

Note : le contenu de source_buffer n'est pas restaurable depuis les seules
3 grandeurs ; le standard ne l'exige pas. Les tests utilisent le mecanisme
dans le cadre du meme buffer (reparsing apres evaluate).

--------------------------------------------------------------------------------
2. C"  (src/interpreter.rs, tokenizer compilation + interpretation)
--------------------------------------------------------------------------------
Avant  : ( -- c-addr u ) stocke uniquement les octets, pousse (addr, len).
Apres  : conforme ISO Forth 2012 (6.2.0765) : execution ( -- c-addr ).

    - Chaine COMPTEE en data space via HERE : 1 + max_len cellules.
      self.memory[buf_addr]          = max_len (octet de longueur)
      self.memory[buf_addr+1 .. +len] = octets de la chaine
    - Compilation : self.compiling_ops.push(Op::Push(buf_addr as i64))
      (une seule valeur : c-addr).
    - Interpretation : self.stack.push(buf_addr) (une seule valeur).

Op::PushStrAddr reste utilise par S" (sans changement).
