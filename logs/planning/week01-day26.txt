1) PRIMITIVES MIGREES (src/interpreter.rs:2010-2163)
   - 73 c@   : check_mem -> read_byte (octet bas cellule) ; sinon mmio_read8
   - 74 c!   : check_mem -> write_byte (masque 8 bits) ; sinon mmio_write8
   - 75 w@   : check_mem -> read_cell & 0xFFFF ; sinon mmio_read16
   - 76 w!   : check_mem -> write_cell(val & 0xFFFF) ; sinon mmio_write16
   - 77 l@   : check_mem -> read_cell & 0xFFFFFFFF ; sinon mmio_read32
   - 78 l!   : check_mem -> write_cell(val & 0xFFFFFFFF) ; sinon mmio_write32
   - 79 fill : check_mem(addr) -> memory[a..min(a+n,4096)] = byte&0xFF ;
               sinon mmio_write8 x n
   - 80 cmove: check_mem(src) && check_mem(dst) -> copie memory clampée
               (chevauchement gere, cnt borne par MAX_MEM-src/dst) ;
               sinon mmio_read8/write8 (comportement anterieur)
   read_byte/write_byte : #[allow(dead_code)] retires (utilises par c@/c!).

2) POURQUOI LA FENETRE
   - Les apps (EDITEUR/KEYLOG/DESKTOP) utilisent c@/c!/fill/cmove sur des
     buffers creates (< 4096) : avant, c@ lisait la VRAIE memoire physique
     aux petites adresses (incoherent avec @/! et allot). Maintenant les
     buffers sont dans self.memory et coherents.
   - heap/mmap (~1 TiB, TESTS/heap.fth) et MMIO haut : >= 4096 -> acces
     reel conserve (heap.fth/ipc_adv.fth/audio.fth intacts).
