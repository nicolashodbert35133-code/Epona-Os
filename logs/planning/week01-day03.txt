4. SIGNATURES NON CONFORMES / A CORRIGER (7)
--------------------------------------------------------------------------------
  c!   ( ch addr -- )   -> MMIO au lieu de l'espace Forth (audit §86)
  c@   ( addr -- ch )   -> MMIO au lieu de l'espace Forth (audit §86)
  c,   ( char -- )      -> HERE += 1 alors que CELL=8 (audit §85)
  fill ( addr u ch -- ) -> MMIO au lieu de l'espace Forth (audit §86)
  rshift ( x u -- y )   -> shift signe (wrapping_shr) au lieu de logique (audit §89)
  type ( addr len -- )  -> lit memory[] (1 octet/cell), incoherent avec c@ (C4)
  create ( "name" -- )  -> avance HERE trop tot (audit §87)

5. IMPLEMENTATIONS HORS NORME (compilateur / variables) (5)
--------------------------------------------------------------------------------
  constant -> Op::ConstantCreate (ne cree pas de vrai mot)       (C1)
  do       -> Op::Do, gere par le parseur                        (C6)
  here     -> variable compilateur, collision avec les chaines   (C2)
  loop     -> Op::Loop, gere par le parseur                      (C6)
  variable -> BTreeMap self.variables, PAS de mot dictionnaire   (C3)

6. CONSTAT MAJEUR (C4) : DEUX MONDES MEMOIRE INCOMPATIBLES
--------------------------------------------------------------------------------
  c@ / c! / fill  -> MMIO brut (i2c_hid::mmio_*)
  type / find / s>f -> self.memory[] (espace Forth, Vec<i64>)
  => Une chaine ecrite avec c! est illisible par type, et inversement.
  => A unifier en Phase 4 (modele memoire : Vec<i64> -> Vec<u8>).
